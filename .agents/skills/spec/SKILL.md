---
name: spec
description: |
  把一次多步骤维护讨论沉淀成可持续使用的规格文档。
  适用于会跨多个会话、多个提交或多个决策点的改动。
argument-hint: "[主题名]"
allowed-tools: Read Write Edit Bash Glob Grep
---

在 `docs/specs/` 下创建或更新规格文件。

工作流：

1. 根据参数或当前主题决定 spec 文件名。
2. 如果 `docs/specs/` 不存在，就先创建。
3. 写入或更新以下结构：
   - 问题
   - 范围
   - 非范围
   - 受影响文档或模板
   - 实施方案
   - 验证计划
   - 开放问题
4. 如果用户已经做出决策，就直接写清，不保留模糊措辞。
5. 最后给出推荐的第一实施切片。

输出格式：

- spec 文件
- 范围摘要
- 开放问题
- 第一实施切片

规则：

- spec 是实施入口，不是会议纪要。
- 保持可执行、可扫描。
- 关键决策还没定时，要明确标成开放问题。
- 章节名保持稳定，方便后续会话快速扫描。
